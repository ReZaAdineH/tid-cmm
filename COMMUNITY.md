# TID-CMM Community

TID-CMM is an open detection capability model intended to improve through practitioner evidence, counter-examples and transparent challenge.

## What the community is for

Useful contributions include:

- challenge a level descriptor with a real counter-example;
- challenge a domain or sub-capability weight with evidence;
- identify an integrity constraint that binds incorrectly or fails to bind when it should;
- contribute telemetry-catalogue improvements;
- correct ATT&CK relationships or derived mappings;
- contribute NIS2, DORA, PCI DSS, CMMC or sector crosswalks;
- share anonymised implementation and assessment lessons;
- contribute anonymised assessment data suitable for future benchmarking;
- improve explanation, documentation, examples and usability.

Agreement is welcome, but evidence that the model is wrong is more valuable.

## Discussions versus Issues

Use **Discussions** for questions, interpretation, implementation experience, research, early ideas and debate.

Use **Issues** for scoped, actionable changes: descriptor challenges, mapping corrections, documentation defects, dataset defects and concrete improvement proposals.

Security findings do not belong in either place. See `SECURITY.md`.

## Canonical governance

Community participation does not silently redefine TID-CMM. Changes to scores, level descriptors, weights, constraints or model structure must be explicit, reasoned, versioned and recorded in the changelog because such changes can move assessment results.

UTIOM remains the overarching operating model. TID-CMM remains its detection measurement module. TIR-CMM remains the response measurement module.

## Quarterly model review

A quarterly public review should group contributions into:

1. descriptor and evidence challenges;
2. scoring/constraint calibration;
3. ATT&CK and telemetry data quality;
4. standards/crosswalk improvements;
5. implementation evidence and benchmarking;
6. documentation and usability;
7. proposed model changes requiring maintainer decision.

## Conduct

Be evidence-led, professional and specific. Challenge ideas rather than people. Do not expose customer data, assessment data that has not been authorised for publication, credentials, production details or private implementation material.
